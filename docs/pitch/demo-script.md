### ✂️ 1. Check-in (จับเวลาสด) — **ตัดจากรอบบ่าย · ใช้ที่บูธเช้า**

> บ่ายพูดตัวเลขแทน: *"มัธยฐาน 1 นาที 26 วินาที จากการจับเวลาจริง 24 ครั้ง ช้าสุด 2 นาที 14"* บนสไลด์ 3

> **ตอนจับเวลาให้เปิด `/checkin/edit/<วันที่วันนี้>` แทน** จะเข้าฟอร์มตรงไม่ต้องกดอะไรก่อน · หรือกด "แก้ไขบันทึกนี้" จากการ์ดสรุปก็ได้ แต่จะกินเวลาเพิ่ม 1 คลิก
> ทางที่สะอาดที่สุด: รัน `npm run refresh:demo-week` เช้าวันจริง แล้วอย่าเช็คอินด้วยบัญชีปาล์มก่อนขึ้นเวที — ฟอร์มจะเปิดมาเป็น wizard ตามปกติ

1. อยู่หน้า `/checkin` ก่อนเริ่มพูด (ดูกล่องเตือนด้านบนก่อน)
2. พูดว่า "จะกรอก check-in ของวันนี้สด ๆ ขอจับเวลา" → เริ่มจับ
3. กดตอบทีละขั้น (4 ขั้น): **กิน → นอน → เคลื่อนไหว → บริบทวัน (พลังงาน + disruptor)**
4. ชี้ให้เห็น: **คำถามเวลามื้อแรกโผล่เฉพาะเมื่อเลือกว่าได้กิน** (progressive disclosure — คำถามเสริมโผล่เฉพาะเมื่อเกี่ยว)
5. กดบันทึก → หยุดเวลา → "ใช้เวลา ~__ วินาที — มัธยฐานทีม 1:26–1:30 จากการวัดจริง 24 ครั้ง" (ตัวเลขเต็มใน qa-results.md)
6. โชว์หน้าสรุปหลังบันทึก — **ชี้ "ตื่นราว …" ที่ระบบคำนวณให้เอง ไม่ได้ถามซ้ำ** (Low Burden)

### 4. AI Coach + guided goal — **อยู่ในบท · งบ 1:00** · สลับไป**สไลด์ 5** ตอนเทียบสองกิ่ง · Plan B = **สไลด์ 13 (สำรอง C)**

### ✂️ 5. Weekly reflection — **ตัดจากรอบบ่าย · ใช้ที่บูธเช้า** · ถ้าถูกถามตอน Q&A เปิด **สไลด์ 12 (สำรอง B)**

2. แบนเนอร์ "สรุปนี้ยังไม่รวมบันทึกล่าสุด" **ตั้งใจให้โชว์** (โผล่ทันทีที่มี check-in ใหม่กว่าสรุปที่ cache ไว้ — เช่นหลังกรอกสดที่บูธ · ระบบเช็คจากบันทึกล่าสุด ไม่ใช่ปฏิทินสัปดาห์) — พูดได้เลยว่า *"ระบบซื่อสัตย์ว่าสรุปนี้ยังไม่รวมวันล่าสุด — เราแยกข้อมูลจากข้อสรุปเสมอ"* · **ห้ามกดปุ่มสร้างสรุปใหม่**

   > 🔴 **ห้ามเตรียมบทว่า "ชี้ลูกศรขึ้น"** — ลูกศรขึ้นหรือลงขึ้นกับข้อมูลสัปดาห์นั้น · ชุด 25 ก.ค. ของปาล์มคือ นอน ↑ · ขยับ ↓ · กินครบ ↓ **ลงมากกว่าขึ้น**
   > ถ้าเจอลูกศรลง ให้ใช้เป็นจุดขายแทน: *"สัปดาห์นี้บางตัวลง ระบบก็แสดงตามจริง ไม่ตัดสิน ไม่ลดคะแนนใคร"* — ตรงกับ key message ของโจทย์มากกว่าการหาลูกศรขึ้นมาชี้
