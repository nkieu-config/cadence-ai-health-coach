## 🔴 ทดสอบเครือข่ายอื่น — ทำก่อนวันงาน แล้วทำซ้ำหน้างาน

ประกาศสั่ง: *"ตรวจสอบ demo บนเครือข่ายอื่น **ไม่ใช่เฉพาะเครื่องที่ใช้พัฒนา**"*

แอปเราไม่มีโหมด offline — **เน็ตล่ม = เดโมจบ** นี่คือความเสี่ยงเดี่ยวที่ใหญ่ที่สุดของทั้งงาน

**ก่อนวันงาน:**

- [ ] เปิด `personal-healthcoach.vercel.app` จาก **มือถือที่ปิด wifi ใช้ 4G/5G** → ล็อกอิน → เดิน guided goal 1 รอบจนจบ
- [ ] เปิดจาก **เครื่องที่ไม่ใช่เครื่องที่ใช้พัฒนา** → ทำแบบเดียวกัน
- [ ] ลองบน **เบราว์เซอร์ที่ไม่ใช่ตัวหลัก** (Safari ถ้าปกติใช้ Chrome)

**หน้างาน ช่วง 10.00 ก่อนเริ่ม:**

- [ ] ต่อ wifi ของห้องแล้วเปิดแอปอีกครั้ง — **wifi งานคนละตัวกับที่บ้าน**
- [ ] ถ้า wifi ห้องช้าหรือบล็อก → **สลับเป็น hotspot มือถือทันที อย่ารอ** และเช็คว่ามือถือคนไหนมีเน็ตเหลือพอ

## ลำดับเช้าวันจริง

| เวลา | ทำอะไร |
|---|---|
| **ก่อนออกจากบ้าน** | รัน `refresh:demo-week` **ทั้ง 3 บัญชี** (ดูคำสั่งด้านล่าง) — ต้องรันบนเครื่องที่มี service-role key + Gemini key |
| **09.00** | ลงทะเบียน · จัดโต๊ะ · เสียบปลั๊ก · ตั้งป้าย |
| **~10.00** | ช่วงพิธี MoU — **ใช้เวลานี้เช็คระบบหน้างาน** ตามหัวข้อเครือข่ายข้างบน |
| **ก่อนกรรมการมาถึง** | เปิด `showcase.pdf` เต็มจออีกหน้าต่าง · login `qa-bot` ค้าง · เปิดวิดีโอสำรองไว้อีกแท็บ · ปิด notification ทุกอย่าง · **ปิดโหมดหลับจอ** |
| **รอบเช้า 60–75 นาที** | เดินตาม [booth-script.md](booth-script.md) |
| **ก่อน 13.00** | ไล่คำถามที่คนจดจดไว้ · ยัดคำตอบที่โดนถามซ้ำเข้ารอบบ่าย · **สลับมาบัญชีปาล์ม** |

```bash
DEMO_EMAIL=qa-bot@example.com  npm run refresh:demo-week   # บัญชีที่เราเดโมตอนเช้า
DEMO_EMAIL=judge@example.com   npm run refresh:demo-week   # บัญชีให้กรรมการลองเอง
npm run refresh:demo-week                                  # ปาล์ม — รอบบ่าย
```

> **ทำไมต้องมีบัญชีที่สาม** — ประกาศบอกว่ากรรมการจะ *"ทดลองผลงาน"* · ถ้าเขาล็อกอินบัญชีเดียวกับที่เราเดโมบนจอ **สิ่งที่เขากดจะเปลี่ยนจอเราทันที** และโควตาแชท 5 ข้อความ/วันจะโดนกรรมการใช้หมดตั้งแต่คนแรก

> 🔴 **อ่านบรรทัดเตือนท้ายผลรันด้วย** — ถ้าขึ้น `⚠️ พบคำที่ต้องอ่านยืนยัน:` ให้เปิด `/coach` หาคำนั้นแล้วอ่านทั้งประโยค
> รอบ 29 ก.ค. ของ qa-bot ขึ้นคำว่า **"ล้มเหลว"** · ตัวจับเป็นแค่การค้นคำ ไม่ได้แปลว่าผิดเสมอไป
> แต่ทั้งงานเราขายว่า **ไม่ตัดสินผู้ใช้** — ประโยคที่กรรมการจะอ่านบนจอต้องผ่านตาคนก่อน

> 🔴 หลังรันเสร็จ **เปิด `/reflection` แล้วหาคำว่า "สิ่งรบกวนตาราง" กับ "วันพิเศษ" — ต้องไม่เจอสักคำ**
> ถ้าเจอแปลว่าสรุปที่ขึ้นจอยังเป็นฉบับก่อนแก้บั๊ก (ต้องเป็น "ปัจจัยรบกวน" คำเดียว) · ตรวจ 28 ก.ค. เคยเจอค้าง 8 จุด — `refresh` สร้างใหม่ให้ แต่**ต้องยืนยันด้วยตาทุกครั้ง**

## แผนสำรอง — เรียงตามลำดับที่จะหยิบใช้

ประกาศเตือนว่า *"Demo อาจมีปัญหาจากอินเทอร์เน็ต API หรือระบบภายนอก"*

| อาการ | หยิบอะไร |
|---|---|
| แอปช้าแต่ยังเปิดได้ | เดินบทต่อ อย่ารอโหลด — ข้ามไปช่วงสไลด์ก่อน แล้ววนกลับ |
| เน็ตล่ม / แอปเปิดไม่ได้ | **วิดีโอสำรอง** (เปิดค้างไว้อีกแท็บตั้งแต่ต้น) |
| วิดีโอก็เปิดไม่ได้ | `showcase.pdf` มีภาพหน้าจอจริงอยู่ทุกหน้า — เดินบทเดิมโดยชี้สไลด์แทน |
| Gemini ล่ม / โควตาหมด | แอปขึ้นข้อความสุภาพไม่ crash → **เล่าว่านี่คือ graceful degradation ที่ออกแบบไว้** แล้วต่อด้วยสไลด์ |
| laptop พัง | เครื่องที่สอง + USB |

> **แผนสำรองที่ดีที่สุดคือพูดถึงมันเอง** — ถ้าเน็ตล่มแล้วเราเปลี่ยนไปวิดีโอได้ใน 5 วินาทีโดยไม่สะดุด นั่นคือคะแนน "บริหารเวลาและแบ่งบทบาทกันดี" ไม่ใช่การเสียหน้า
